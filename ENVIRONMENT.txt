armteam — Environment Overview
==============================

What we need, and what each part does. Listed from the bottom of the stack up.
All of it is installed by run_requirement.sh (package list: requirement.txt).


Summary
-------

Component          Version / package               In one line
-----------------  ------------------------------  ----------------------------------------------
Ubuntu             24.04 LTS                       Operating system everything runs on
ROS 2              Jazzy                           Lets robot programs talk to each other
CycloneDDS         rmw_cyclonedds_cpp              Network layer that carries ROS 2 messages
MoveIt 2           ros-jazzy-moveit                IK, motion planning, collision checking
rviz2              part of ros-jazzy-desktop       3D view of the robot and its plans
Gazebo + ros_gz    Harmonic, ros-jazzy-ros-gz      Physics simulator, bridged to ROS 2
ros2_control       ros-jazzy-ros2-control          Same control interface for sim and real robot
colcon, rosdep     ROS 2 dev tools                 Build the workspace, install dependencies
Python libraries   numpy, PyYAML, matplotlib       Run the experiment, read configs, plot
Browser desktop    XFCE, TigerVNC, noVNC           See rviz2 / Gazebo on a RunPod pod (no monitor)

Related files (not software)
  URDF   Robot description from the TA: links, joints, joint limits, collision shapes.
         The ONLY source for INDEX01's joint count, reach and torque limits.
  SRDF   MoveIt's add-on to the URDF: planning groups (arm_only, arm_torso) and the
         Allowed Collision Matrix (ACM). Generated by MoveIt Setup Assistant.


What each component does
------------------------

Ubuntu 24.04
  - ROS 2 Jazzy and MoveIt 2 binaries are published only for Ubuntu 24.04, so any
    other version fails at install time.
  - Windows and WSL2 are not supported: MoveIt 2 does not run properly there.

ROS 2 Jazzy
  - Robot software is split into small programs (nodes): one reads the robot model,
    one computes joint angles, one draws the screen, and so on.
  - ROS 2 is the common framework that lets these nodes exchange messages.
    Think of it as the operating system layer for robot software.
  - "Jazzy" is the distribution name. Docs for other distributions (e.g. Humble)
    use different package names and APIs, so check that a URL contains "jazzy".

CycloneDDS (rmw_cyclonedds_cpp)
  - The middleware that actually carries data between ROS 2 nodes.
  - Recommended by the MoveIt docs.
  - EVERY team member must use it: nodes on different middleware cannot talk.
  - run_requirement.sh sets RMW_IMPLEMENTATION=rmw_cyclonedds_cpp in ~/.bashrc.

MoveIt 2  (the core tool of this project)
  - Inverse kinematics (IK): "which joint angles put the hand at this point?"
    This is the heart of the reach experiment (2-2).
  - Collision checking: does the arm hit the torso in that pose?
  - Motion planning: find a path from the current pose to the goal pose.
  - Setup Assistant: builds the SRDF (planning groups + ACM) from the URDF.

rviz2
  - Draws the robot model, goal markers and planned motions in 3D.
  - Used to check that the robot moves (1-3) and to record the demo video.
  - It only visualises what ROS 2 tells it. No physics, and it does not move the
    robot on its own.

Gazebo + ros_gz
  - A virtual world with physics: gravity, inertia, contact, torque.
  - ros_gz bridges Gazebo and ROS 2.
  - The reach study itself relies mainly on MoveIt IK + collision checks, so
    Gazebo plays a smaller role: checking that motions are physically feasible
    and running the robot closer to real conditions.

ros2_control
  - The control layer that sends commands like "move this joint to this angle"
    to the real motors or to the simulator.
  - Lets simulation and the real INDEX01 use the same controller stack, which
    makes moving to the real robot easier.

colcon / rosdep
  - colcon builds the packages in the workspace (/workspace/ros2_ws), e.g. the
    MoveIt config package: `colcon build`.
  - rosdep finds and installs the system dependencies a package needs.

Python libraries (numpy, PyYAML, matplotlib)
  - Run the reachlab experiment code, read config/planning_groups.yaml and plot
    success rate vs. distance.
  - Installed with apt (python3-*) rather than pip, which Ubuntu 24.04 restricts.

Browser desktop (XFCE + TigerVNC + noVNC, RunPod only)
  - RunPod pods have no monitor. This serves a desktop in the browser so rviz2
    and Gazebo windows can be seen.
  - Start it with ~/start_gui.sh and open HTTP port 6080 from RunPod's Connect menu.
  - Skipped with `bash run_requirement.sh --headless`.


Do we have a digital twin?
--------------------------
Not rviz2 alone. Together the pieces form a digital-twin-like setup:
  URDF (virtual model) + Gazebo (physics) + ros2_control (link to the real robot)
  + rviz2 (visualisation).
Our task does not need a full digital twin: it measures reach with MoveIt IK and
collision checks, and uses rviz2 to inspect results and record the demo.


Hardware
--------
No dedicated GPU needed. rviz2 rendering is light; integrated graphics are enough.
